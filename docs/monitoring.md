# 美国监控 MVP 的运行与验证

仅支持美国官网、美国 Outlet 和 REI 商品链接，报价币种为 USD，只读取公开商品页。通过页面 Product / ProductGroup JSON-LD 精确匹配 SKU、颜色、尺码、币种、全新商品条件、公开价格和库存。REI 额外核对 Arc'teryx 品牌归属及变体所属商品组。

## 使用流程

1. 在仓库根目录启动 `PYTHONPATH=src python3 -m arcteryx_prices serve --port 8080`。
2. 在本地工作台粘贴产品链接，点击读取变体，选择颜色和尺码。
3. 选择目标价、已观测新低或补货规则。目标金额使用 USD。
4. 系统保存历史、调度采集，并在满足规则且二次复核成功后生成站内提醒。

前端导航分为关注清单、价格记录、提醒中心和购买指南。关注清单支持商家、状态和文本筛选，价格以 USD 排序。点击卡片的“设置提醒”可以修改规则、目标价和频率；价格记录页可选择任一美国关注查看真实观测和覆盖天数。购买指南链接到已核实的美国官方条款与仓库中的完整攻略。

旧版加拿大关注在初始化时停用，后续不能恢复、检查或由调度器采集；已有关注、报价和提醒记录保留供审计，产品 API 与界面只展示美国范围。加拿大商家接入已移出计划。

断线时界面隐藏当前报价并暂停写操作；重新连接后恢复。自动刷新不会覆盖正在填写的表单；轮询更新保留对应操作按钮的键盘焦点。单日记录不绘制虚假的趋势，缺失日期也不会用连线填补。

每个关注默认 60 分钟检查一次，可通过 CLI 将 `interval_minutes` 设置为 30–1440 分钟。网页服务每 30 秒检查哪些关注已到期，也可单独执行 `worker --poll-seconds 30` 持续运行调度器。另一种方式是由系统定时任务调用 `run-once --notify gmail`：检查已到期关注、发送邮件，然后退出，不必一直开着网页。多个进程共享数据库时，lease 与原子到期检查避免同一关注并发重复采集。电脑关机、休眠或断网期间不能正常监控。

Gmail 监控邮件需要显式配置并运行 `run-once --notify gmail`；`gmail-test` 可主动发送一封配置测试邮件，详见 [邮件设置与定时检查](email-alerts.md)。`serve`、`worker` 和 `check` 本身不发邮件。当前服务只绑定本地地址，并对 HTTP Host、同源写入、请求大小和 CSRF token 进行检查。

## 提醒判定

| 规则 | 触发条件 |
| --- | --- |
| `target` | 明确现货且价格不高于目标价；首次有效命中也会提醒 |
| `new_low` | 该关注已有合格历史，本次价格严格低于此前观测最低；首次采集不会被称为新低 |
| `restock` | 上一次明确库存为缺货，本次变为现货；若设置目标价，还必须达标 |

候选提醒会再次读取页面。复核失败、价格/库存变化、关注被暂停或配置发生变化时，不生成提醒。持续处于同一促销条件时不反复提醒；明确回升或缺货等事件解除条件后可以重新触发。临时采集失败不当作促销结束，也不伪造补货转换。

## 失败与历史

`monitor_checks` 记录每次主要检查/复核的成功或失败状态，保留成功报价及响应内容哈希。网络失败、HTTP 拒绝、解析失败、身份不匹配、库存不明确分别记录。失败不生成零价或缺货观测。

检查记录还保留 HTTP 状态、可重试标记及服务器的 Retry-After 截止时间。临时网络错误、HTTP 408/429/5xx 从正常间隔开始逐次倍增等待，最多 24 小时；有效的服务器截止时间可以要求更长等待，不能被本地上限缩短。成功后清零连续失败次数。解析和身份错误按正常间隔检查，不触发密集重试。

`monitor_host_cooldowns` 持久化 HTTP 429 或带 Retry-After 的 503 所要求的主机等待。自动检查、手动立即检查、API/CLI 读取变体都遵守；重启、暂停再恢复、修改提醒设置或强制检查不能绕过它。不同主机独立处理；已在途请求不保证能取消。前端显示失败次数与下次可检查时间，等待不写入假价格或修改促销去重状态。

每轮调度使用最多 8 个页面的临时缓存，相同 URL 的不同变体共用初次页面和实际采集时间；下一轮重新读取。提醒复核必定绕过缓存。`last_success_at` 表示成功页面的实际取得时间，`last_checked_at` 表示本次检查完成时间，复用页面不会延长其报价有效期。设计来源及取舍见 [开源方案比较](open-source-monitoring-review.md)。

只有最近检查成功、未超过关注间隔且明确现货时，界面展示当前可购价格。否则当前价为空，历史仍可查看。已知缺货可以保存报价作为原始观测，但不进入新货现货最低价或均价。

所有时间使用 UTC；价格使用整数美分。每个关注按 URL+SKU 形成独立身份，避免猜测跨页匹配。完整历史指标见 [数据库说明](database.md)。

## 真实验证

实测记录位于 [live-monitor-validation.json](../research/live-monitor-validation.json)。2026-10-26（America/Denver）的首次端到端验证为：

| 页面 | 颜色 / 尺码 | SKU | 当次结果 |
| --- | --- | --- | --- |
| 美国官网 Beta Jacket | Black / S | X000010868009 | USD 400，现货 |
| 美国 Outlet Alpha SL Jacket | Black / M | X000010287010 | USD 350，现货 |
| 美国 Outlet Alpha SL Jacket | Black / XS | X000010287008 | USD 350，缺货；不显示为当前可购价 |

以上为首次美国官方来源的单次公开标价，不含税运，不是价格承诺或完整历史。原始验证 JSON 保留最初调查快照，包括已移出产品范围的旧加拿大记录。后续新增 REI 美国站验证见 [零售商记录](../research/third-party-retailers.json)，长周期稳定性仍需持续观察。美国历史促销参考另行导入和展示，不能当成当前关注的完整价格曲线，详见 [第三方与历史说明](retailers-and-history.md)。

初次网络检查曾被策略阻止；后续正确商品路径已可读取。旧的无型号后缀链接出现过 404/406，不能据此认定所有官网不可访问。当前使用明确标识监控器的兼容 User-Agent，保留代理和 TLS 验证，不绕过认证或验证码。

## API 与开发

| 方法和路径 | 用途 |
| --- | --- |
| `GET /api/health` | 检查服务与数据库可访问性，不代表所有远端来源健康 |
| `GET /api/state` | 美国关注、历史指标、站内提醒、来源能力、历史参考和写请求所需 token；scope 为 US/USD |
| `GET /api/history-evidence` | 历史证据、来源和是否经过精确变体核验；只读 |
| `POST /api/discover` | 用 `{ "url": "..." }` 读取可验证变体；来源等待时返回 429 和 `retry_at` |
| `POST /api/watches` | 添加关注 |
| `PATCH /api/watches/{id}` | 调整 `enabled`、提醒规则、目标价或间隔 |
| `POST /api/watches/{id}/check` | 立即检查，JSON 请求体为 `{}` |

写请求使用 `Content-Type: application/json` 和 `X-CSRF-Token`。前端不依赖外部 CDN。

执行 `PYTHONPATH=src python3 -m unittest discover -s tests -v` 运行离线测试。测试和浏览器交互中的合成价格使用临时数据库；正式工作库只保存实际采集的价格。

前端端到端测试：`node tests/frontend.e2e.cjs`，需要测试机提供 Playwright 和 Chromium。测试自动创建本地合成 API 服务，检查美国变体发现、创建和编辑关注、商家筛选排序、旧地区数据隐藏、断线恢复、历史缺口、移动端与焦点保留，不依赖真实商品的价格变化。
